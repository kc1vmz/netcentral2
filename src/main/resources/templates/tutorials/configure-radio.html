Description of task

Connect Net Central to a radio through a terminal node controller (TNC) or compatible packet interface so it can receive APRS traffic and transmit net messages and object beacons. Each connection is a communication instance. You can configure more than one instance and choose which ones each net or object uses.

This tutorial covers KISS, TNC2, and Kenwood radio connections. APRS-IS Internet connections are a separate configuration activity.

Prerequisites

  • Sign in to Net Central with an Admin or Sysadmin account.
  • Have a radio, antenna, and compatible TNC or packet interface connected and configured for your intended APRS channel. Prepare the radio's packet mode, audio levels, and connection settings according to its documentation.
  • For a serial connection, connect the device to the computer running Net Central and know its serial device name and baud rate. The port list comes from that computer, even if you use a browser on another computer.
  • For a TCP connection, have a reachable KISS or TNC2 service connected to the radio, and know its host address and listening TCP port.
  • Know the digipeater path you intend to use, and any KISS channel or device initialization commands required by your interface. For Kenwood Serial, also have the callsign to configure as MYCALL.

Steps to accomplish

  1. Open Communications and select Add connection.

  2. Select the appropriate Type:

    TypeUse when
    KISS SerialYour TNC exchanges KISS frames over a serial connection.
    KISS TCPA network-accessible TNC or packet program exposes a KISS TCP endpoint.
    TNC2 SerialYour serial interface exchanges complete TNC2 text lines, such as SOURCE>DESTINATION,PATH:payload.
    TNC2 TCPYour TCP service exchanges those complete TNC2 text lines.
    Kenwood SerialYou are using the supported Kenwood command-mode TNC mechanism rather than KISS or a complete-line TNC2 interface.

    TNC2 Serial is not a general command/converse-mode driver. Choose the type that matches the interface's actual protocol.

  3. Set State and Transmission. New connections default to Active and Allow transmission. To verify reception first, select Receive only. Choose Paused if you want to save the configuration without opening the connection yet.

  4. Enter the connection properties:

    • Serial: Choose the Serial device and matching Baud rate. Windows devices commonly have names such as COM3; Linux devices may appear as /dev/ttyUSB0 or /dev/ttyACM0. The baud rate is the computer-to-TNC serial speed, not the over-the-air packet speed.
    • TCP: Enter Host and TCP port for the packet service. Use the port configured in that service; do not assume the displayed default is correct. A host of localhost means the computer running Net Central.
    • KISS Serial or TNC2 Serial: Enter Initialization command 1 and Initialization command 2 only when needed. Leave them blank for an already prepared interface. Net Central sends a carriage return after each configured command.
    • Kenwood Serial: Enter Login callsign / Kenwood MYCALL. Net Central automatically performs RESET, MYCALL, and UNPROTO setup; there are no manual initialization-command fields for this type.

  5. Set the radio routing fields. Enter the Digipeater path appropriate for your operation, or leave it empty for direct transmission. For KISS, set KISS port/channel to the channel your TNC uses, commonly 0 for a single-channel interface. Transmit spacing (milliseconds) defaults to 1000; retain that starting value unless your setup requires different pacing.

  6. Select Save connection. Net Central derives the instance name from its properties. An Active instance begins connecting; a Paused instance waits until you select Resume and confirm.

  7. Choose where outgoing traffic should go. Open Default communication selection for traffic without an explicit net or object selection. Choose all eligible instances or only selected instances, select Update, and confirm. Also review the Communications selection when creating or editing each net or object. A working connection must be included in the applicable selection to carry that traffic.

  8. If you started with Receive only, select Edit, change Transmission to Allow transmission, and save when you are ready to test outgoing traffic.

Verifying success

  1. On Communications, select Refresh. Confirm that the instance is Active and its connection state settles at CONNECTED or RECEIVE_ONLY as appropriate. Review any displayed error if it remains CONNECTING or RETRYING.
  2. Receive a known APRS transmission. Check that Received increases and Last packet updates. Open Explorer to look for the station or object. A station appears on the map only when a usable position has been received.
  3. For a transmit test, use a net or object that selects this instance and send a suitable message or beacon. Confirm that Sent increases, and verify reception on another station or receiver. A local Sent count alone does not prove reception over the air.
  4. For a directed message, first hear the destination on an eligible connection. Net Central uses the receiving connection or an eligible recently heard route; a no route result can mean the destination has not been heard, rather than a failed radio interface.

Additional considerations

  • Serial ownership: Give each serial instance its own port. KISS Serial, TNC2 Serial, and Kenwood Serial instances cannot share the same serial device. Close other programs that have the port open. On Linux, the account running Net Central must have permission to access the device.
  • Missing ports: Check the cable, device power, and driver, then reopen the connection dialog to reload the device list. Device names may change after reconnecting hardware.
  • Kenwood identity: Kenwood transmits using the configured MYCALL as the RF source callsign. Do not assume it can substitute every net or object callsign as the source in the same way as a KISS interface. Verify operation with your particular radio model.
  • Multiple connections: Multiple instances of each transport are supported. Selecting all eligible instances includes future instances too; selecting an empty set allows no transmissions through that selection.
  • Pause versus Receive only: Paused stops the connection. Receive only keeps reception available while disabling outgoing transmissions.
  • Packet acknowledgments: Net Central handles APRS message ACK/REJ consistently across its radio transports. An acknowledgment is different from a successful local write to the TNC.
  • Troubleshooting: Review Failed, Discarded, Queued, and the displayed error on Communications. Check protocol, baud rate or TCP endpoint, radio settings, transmission permission, and routing selection before changing unrelated settings.
