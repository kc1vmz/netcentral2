Description of task

Send a simple text email through Net Central's Winlink tool. The tool communicates with WLNK-1 using APRS messages, handles the password challenge, and submits the recipient, subject, and message text.

This tool works independently of nets. It uses the default communication selection rather than a particular net's selected instances.

Prerequisites

  • Sign in to Net Central and have a Winlink callsign and password for the identity you intend to use.
  • For a User account, configure your callsign in My account. The sender must have the same base callsign as your account; an administrator can use a different sender.
  • Have an administrator configure and verify an APRS communication instance that allows transmission and can exchange messages with WLNK-1.
  • Review Default communication selection on Communications. It must include an eligible connection with a route to WLNK-1.
  • Know the intended recipient and prepare a short plain-text subject and message. Keep Net Central running while the exchange completes.

Steps to accomplish

  1. Open Tools → Winlink.

  2. Enter Callsign using the Winlink identity that will originate the message. Do not enter a net callsign unless it is the appropriate authorized identity for this operation.

  3. Enter the corresponding Winlink password. This is not your Net Central account password or APRS-IS passcode.

  4. Enter one Recipient address or callsign accepted by the destination service. The form supports a single recipient string, not a comma-separated address list or a display name such as Name <address>.

  5. Enter an optional Subject. Keep it brief: the tool permits up to 50 subject characters, and the combined recipient and subject must also fit the APRS submission header's 67-character limit, including its command and spaces.

  6. Enter the Message, up to 2,000 characters. Use plain text; there is no attachment field. Short messages require fewer APRS packets.

  7. Review the sender, recipient, subject, and body, then select Send via Winlink. This submits immediately without a second confirmation dialog.

  8. Review the status shown above the tool. Net Central sends the login request to WLNK-1, responds to its challenge, and, if accepted, submits the message in APRS-sized parts. Do not repeatedly press Send while that exchange is in progress.

Verifying success

  1. Check the submission result for an immediate error. WAITING means the request is awaiting the gateway exchange; it does not mean the email was delivered.
  2. Review the selected connection on Communications, or ask an administrator to do so. Check for outgoing packets and incoming replies from WLNK-1, and inspect any connection errors.
  3. Confirm receipt with the intended recipient or through an appropriate Winlink client. Even a SENT session state records completion of the outgoing packet group, not proof of final email delivery or that a person read the message.
  4. Be aware that the tool's result text is the status returned when the form was submitted; this page is not a live session-progress display. Do not refresh a submitted form merely to check progress, because the browser may offer to resubmit it.

Additional considerations

  • No route: NO_ROUTE means the tool could not select an eligible route to WLNK-1. Check default communication selection, recent routing information, connection availability, and transmission permission. Having a connection configured is not sufficient by itself.
  • Authentication: Net Central handles the gateway's challenge automatically. Verify the exact callsign and Winlink password if the exchange is rejected. The password is held temporarily for the exchange and cleared after responding to the challenge or when the session is cleaned up.
  • One request per callsign: A session already registered for the sender prevents another request for that callsign until it is removed or expires. Sessions expire ten minutes after creation; repeated submissions can produce an existing-request error rather than another send.
  • Length and formatting: Recipient characters are limited to letters, numbers, and @ . _ + -. The tool splits the body into chunks of up to 50 characters. Keep wording concise and avoid relying on elaborate email formatting.
  • Restart behavior: Winlink sessions are kept in memory and do not survive an application restart. If an exchange is interrupted, verify whether the recipient received the message before trying again.
  • Radio and Internet: The tool uses APRS messaging, not a direct SMTP connection or a local Winlink mailbox client. The chosen radio or APRS-IS path must support the gateway exchange.
  • Kenwood identity: Kenwood Serial uses its configured MYCALL as the RF source. Ensure that identity is appropriate for the callsign used by this tool so gateway replies can match the session.
  • Duplicate prevention: If the outcome is uncertain, investigate the connection and recipient's mailbox before manually sending the same message again.
