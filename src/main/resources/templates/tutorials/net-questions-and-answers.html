Description of task

Ask questions in a running net and collect answers by participant callsign. Use Net Monitor to ask questions, record responses received through another channel, and review answers. Checked-in participants can also ask and answer through APRS messages.

Choose Text for a free-form question or Strip for a structured Request for Information with named fields. For example, BEDS/Facility(X)/Available(NN)// requests a facility name and available-bed count. Strips use masks to validate values and display answers in columns for comparison.

Questions and answers remain with the net and are available in Archives and the Q&A Report after completion.

Prerequisites

  • For browser controls, sign in as the net owner or an administrator authorized to manage it. Select a running net; scheduled definitions and archived nets cannot accept new questions or answers.
  • Have intended participants check in. Answers can only be recorded for currently checked-in callsigns.
  • Verify that selected communication instances are available, allow transmission, and have eligible routes to participants.
  • Prepare a concise question. For a strip, decide which fields and masks to use. Each definition needs an embedded name, at least one Label(MASK) field, and a final //.
  • Administrators and system administrators can maintain reusable strips in Settings. Other signed-in users can view the library; permission to manage a net is still required to ask questions through its browser controls.

Steps to accomplish

  1. For a reusable strip, open Settings / Strip Library. Select Create strip. Enter a unique strip name, such as Bed availability, and a definition such as BEDS/Facility(X)/Available(NN)//. Select Create. Validation errors appear in the editor; correct them and retry. Use Edit to rename or update an entry. Names are unique regardless of capitalization.

    The strip name is used in the selection list. The embedded name (BEDS) appears in brackets on issued questions and answers. These names can differ.

  2. Open Net Monitor and select the intended Running net in the carousel. Verify its callsign and name.

  3. In Questions, select Ask question and choose Type:

    • Text: Enter a free-form Question without a radio-command prefix.
    • Strip: Choose a named library entry under Shared template. Request strip becomes read-only. Select Create ad-hoc request strip to make that field editable and enter a definition for this question. This does not add an entry to the library.

    Enter only the definition, not QS or an assigned identifier. For example, foo/bar/test// is invalid because its fields lack masks. Use foo/bar(X)/test(X)// for two free-text fields.

  4. Select Ask participants and confirm sending. Net Central assigns a question number or strip identifier, such as S1, and sends it to currently checked-in participants. Cancel leaves the question unsent.

  5. Select the question in Questions. Text questions show a number such as Q 1; strips show an identifier and embedded name such as S1 [BEDS]. Answers displays responses for the selection.

  6. To enter a response received by voice or another channel, select Record answer. Enter Question number (for example, 1 or S1) and Participant callsign, including its SSID. Text questions use a single Answer field. Strip questions present separate inputs for each field with its mask; enter values without labels or slashes. Leave a field empty when unknown; the dialog encodes a single-space placeholder.

  7. Review the identifier, callsign, and values, then select Save answer. Saving is immediate, without a second confirmation. Close is at the bottom of the dialog. Select the question to review the recorded response.

Using a radio or APRS client

After checking in, send these APRS messages to the running net's callsign:

PurposeExample
Ask a text questionQ Can you operate until 1800?
Answer text question 1A 1 Yes, available until 1800
Create a strip questionQS BEDS/Facility(X)/Available(NN)//
Answer strip S1A S1 Lincoln/25//
Retrieve unanswered text and strip questionsQL
Retrieve a question and its answersQR 1 or QR S1

An issued strip looks like QS S1/BEDS/Facility(X)/Available(NN)//. Use its actual assigned identifier in your answer. Include only values in the original field order, separated by slashes and ending in //. Omit BEDS and the field labels. For an unknown value, use exactly one space: A S1 Lincoln/ //. Do not omit its separator.

For BEDS/Meals(#)//, answer with A S1 5// using the actual identifier. The # mask permits exactly one digit. Use NNN in a new definition when counts from one to three digits are needed. Net Central sends a thank-you response after accepting a radio question or answer.

Verifying success

  1. Confirm the question appears once with the expected text and identifier. For strips, check the embedded name in brackets.
  2. Have a checked-in participant verify reception on their APRS client. Browser visibility proves the question was recorded, not that every transmission arrived.
  3. Select the question and verify the responding callsign and values in Answers. For strips, check each field column and the original response string. Unknown values appear as (blank); confirm these are intentional.
  4. Retrieve responses by radio with QR 1 or QR S1. QL should no longer include a question that participant has answered.
  5. Resume updates if paused. Check the selected question before treating an empty Answers section as a missing response. After securing the net, verify its questions and responses in Archives or Generate Q&A Report.

Additional considerations

Choosing strip masks

MaskAccepted value
XFree text within the strip's character and length limits.
A, AAAExactly one or three uppercase letters, respectively.
N, NNNOne digit, or one to three digits, respectively.
#, ###Exactly one or three digits, respectively.
-##.##Two digits on each side of a literal decimal point, with an optional minus sign.
Y,NY or N.
DDHHMMDay, hour, and minute in UTC.
DDHHMMZ, DDHHMMLDay, hour, and minute with the matching Z (UTC) or L (local) suffix.
MM-DD-YYYYA valid date in the specified format.
  • Strip characters: Slashes separate fields and cannot appear inside values. Line breaks, non-ASCII text, and APRS-reserved characters { } | ~ are not allowed.
  • Strip length: Each request and response must fit one 67-character APRS message, including its command and identifier. Retrieval also needs room for the responding callsign. Oversized strips are rejected, not split or truncated. Keep embedded names, labels, and values concise.
  • Text length: Browser text-question and answer fields accept up to 500 characters, but APRS has shorter transport limits. Keep operational text brief.
  • Library changes: Editing or removing a library entry does not change issued questions. To change an issued strip's fields or masks, ask a new question. Strip identifiers belong to the net and survive a restart.
  • Partial and invalid answers: An accepted partial answer counts as answered and stops unanswered-question reminders for that participant. Invalid answers do not replace a valid answer. Correct the reported problem and submit again.
  • One answer per callsign: Another valid answer to the same question replaces that callsign's current answer. Answer events remain in net history. Review the callsign and identifier before correcting a response.
  • Answer delivery: Answers are stored for review, not automatically broadcast to every participant. Use Answers or QR to review them.
  • Late arrivals and missing responses: Initial delivery targets participants checked in at that time. Later arrivals can use QL. Question reminder settings apply to strips as well as text questions. Check participation, the identifier, route availability, and communication status if a response is missing.
  • Archives: After securing the net, select it in Archives to review Questions and Answers or Generate Q&A Report. Archived records are read-only.
