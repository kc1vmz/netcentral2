Description of task

Create a Net Central General Resource object to advertise a location and maintain named resource values. For example, a supply location might have values such as WATER=AVAILABLE or CAPACITY=20.

The Type field calls this Net Central General Resource. Unlike a Generic APRS Object, it includes a Resource values section and supports authorized key=value radio updates. It does not use the specialized Shelter or EOC report forms.

Prerequisites

  • Sign in to Net Central. The creating account or an authorized administrator can manage the object afterward.
  • Choose an available object callsign of up to nine characters and know its location. Avoid conflicts with existing managed objects or running nets.
  • Prepare a short comment, choose an APRS symbol, and decide which named values the resource should hold.
  • Have an administrator configure and verify the radio or Internet communication instances the object will use.
  • For radio updates, have an administrator review Settings → Object security so the intended stations are authorized to update the object.

Steps to accomplish

  1. Open Explorer and select Create object.

  2. Enter the object's Callsign and choose Net Central General Resource in Type. This is the creation form's default type.

  3. Set Object location. With Manual entry, enter decimal-degree latitude and longitude, using negative values for south and west. Alternatively, select Use map, click the location, and drag the marker to adjust it. Both coordinates are required.

  4. Enter a Comment of up to 80 characters identifying the resource, and choose the appropriate APRS symbol.

  5. Leave Active (send periodic beacons) checked to advertise the object. In Communications, keep All eligible instances, including future ones or choose Selected instances and check the intended connections. An empty selected set transmits nowhere.

  6. Review the settings, select Create, and confirm the creation dialog. To abandon the form, select Cancel and confirm discarding changes.

  7. On the object's details page, locate Resource values and select Add. Enter a Name and Value, such as WATER and AVAILABLE. Select Add and confirm. The pair appears on its own line in the list.

  8. Repeat for additional values. To replace an existing value, add the same name with its new value and confirm. To delete a pair, select its Remove button and confirm the removal.

Reading and updating values by radio

Address APRS messages to the object's callsign:

MessagePurpose
RRequest the resource's stored values.
WATER=AVAILABLESet the WATER value to AVAILABLE when the sending station is authorized.
?NCGRVRequest the stored key=value pairs.
?INFORequest identifying information and supported queries.
?CMDRequest the supported command list.

Use short, consistent names and values for radio exchanges. Radio update permissions do not automatically follow from a station knowing the object's callsign.

Verifying success

  1. Confirm that Object Details shows the intended callsign, location, status, symbol description, and comment, and that the Resource values section is present.
  2. After adding a value, verify the displayed name and value. Reload the page to confirm it was saved. After removing a pair, confirm that it no longer appears.
  3. Find the object in Explorer using an appropriate resource filter, select it, and confirm its map location. Use View details to reopen its page.
  4. From an eligible APRS connection, send R to the object's callsign and verify the returned values. For a radio update test, send a key=value message from an authorized station, then reload the object's details and confirm the change.
  5. Verify beacon reception using another APRS client or receiver. If needed, ask an administrator to review the selected instances on Communications.

Additional considerations

  • Choosing the right object: Use this type for flexible named values. Choose Generic APRS Object for a simple location marker, or Shelter/EOC for their predefined operational reports.
  • Replacing values: Adding an existing name overwrites its current value after confirmation. Use the same spelling consistently and verify the result before making further changes.
  • Browser versus radio: Browser edits require object-management permission. Radio writes are governed by Object security rules. If a radio update fails, review the sender's authorization as well as connection and routing availability.
  • Editing configuration: Use Edit for location, comment, symbol, and communication settings. The callsign is read-only when editing. Resource values are managed separately on the details page.
  • Beaconing: Settings → Announcements controls Beacon seconds. Saving a value locally does not prove that another station received a beacon or query response.
  • History: The Resource values section shows the current pairs; it is not a visible revision-history viewer. Preserve any earlier values you need before replacing or removing them.
  • Withdrawal: For an active object you manage, Withdraw object asks for confirmation, sends a withdrawal, and deletes the object and its associated data. Its callsign can then be reused. This is not the net archive workflow, and remote reception is not confirmed before deletion.
  • Connection selection: All eligible instances includes future connections. Select particular instances when the resource should be advertised only on specific paths.
  • Kenwood: Kenwood Serial uses its configured MYCALL as the RF source, while the object has its own identity within the APRS object packet. Verify both the advertised object and directed-message behavior with your setup.
