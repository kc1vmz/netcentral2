Description of task

Connect Net Central to the APRS Internet Service (APRS-IS) to receive APRS traffic over the Internet and, when authorized and enabled, send APRS messages and object beacons. No local radio or TNC is required for this connection.

The APRS-IS connection is a communication instance. You can use it alongside radio instances and choose which connections each net or object uses.

Prerequisites

  • Sign in to Net Central with an Admin or Sysadmin account.
  • Ensure the computer running Net Central has Internet access and can make an outbound TCP connection to your chosen APRS-IS server.
  • Have the APRS-IS server's host name and TCP port. Choose an endpoint intended for APRS clients and confirm whether it supports server filters.
  • Have the callsign you intend to use for the APRS-IS login and its corresponding APRS-IS passcode if you will transmit. This is separate from your Net Central account email and password.
  • Decide which area or stations you want to monitor, and prepare a server filter supported by your selected server. For receive-only access, use passcode -1 with transmission disabled.

Steps to accomplish

  1. Open Communications and select Add connection.

  2. Select APRS-IS as the Type.

  3. Choose the State and Transmission. New connections default to Active and Allow transmission. Select Receive only to start by listening, or Paused to save without connecting yet. Passcode -1 requires Receive only.

  4. Enter the Host and TCP port supplied for your chosen APRS-IS endpoint. The form initially offers port 14580; use your server's actual port. Enter a host name or address, not a web page URL.

  5. Enter your APRS-IS callsign in Login callsign / Kenwood MYCALL. For this connection type, this field is the APRS-IS login identity. Enter the corresponding numeric Passcode, or -1 for receive-only operation. Do not enter your Net Central password.

  6. Enter the Server filter for the traffic you want to receive. Net Central adds the filter keyword when building the login request, so enter only the filter expression. Use the syntax documented by your selected APRS-IS service. If you leave this blank, you have not requested a custom filter; the traffic received depends on the endpoint's behavior.

  7. Select Save connection. Net Central derives the instance name from the host, port, and login callsign. An Active instance begins connecting immediately. If you saved it as Paused, select Resume and confirm when ready.

  8. Review Default communication selection for traffic without an explicit net or object selection. Choose all eligible instances or only selected instances, select Update, and confirm. Also review the Communications selection of each net or object that should use this APRS-IS instance.

  9. When ready to transmit, select Edit, supply a valid passcode if needed, choose Allow transmission, and save. When editing an existing APRS-IS connection, leaving Passcode blank retains the saved passcode.

Verifying success

  1. On Communications, select Refresh. Confirm the instance is Active and reaches CONNECTED for verified transmission-enabled operation, or RECEIVE_ONLY when transmission is disabled or the server reports an unverified login. CONNECTING or RETRYING indicates that setup has not yet completed; review the displayed error.
  2. Check that Received increases and Last packet updates as traffic arrives. Open Explorer and look for stations or objects covered by your filter. Quiet traffic or a restrictive filter may mean there is nothing new to display.
  3. For a transmit test, use a net or object configured to select this instance and send a suitable APRS message or beacon. Confirm that Sent increases, then verify reception through another APRS client or the intended recipient. A Sent count records a local send; it does not by itself confirm delivery.
  4. For directed messages, first receive traffic from the destination through an eligible connection. Net Central preserves its receiving-connection and recently-heard routing rules; an APRS-IS connection alone does not guarantee that a directed message has a route.

Additional considerations

  • Authentication: Allow transmission does not override the server's authentication result. If you expected CONNECTED but see RECEIVE_ONLY, check the transmission setting, callsign, passcode, and server response.
  • Filters and routing: A filter that excludes a destination's traffic can prevent Net Central from learning a route to that station. Choose a scope that supports your operation without collecting unnecessary traffic.
  • Internet versus radio: Sending to APRS-IS is not proof that a packet was transmitted over RF. Delivery to a radio station depends on the available APRS infrastructure and its forwarding behavior.
  • Multiple instances: You can configure several APRS-IS and radio connections. Avoid accidentally configuring duplicate TCP endpoints or selecting more outgoing connections than intended. All eligible instances includes future instances; an empty selected set allows no transmissions through that selection.
  • Pause versus Receive only: Paused stops the connection. Receive only keeps reception available while preventing outgoing transmissions.
  • Connection problems: Check host spelling, DNS, the configured port, outbound firewall access, and server availability. The connection originates from the Net Central host, not the computer displaying your browser.
  • Monitoring: Review Failed, Discarded, Queued, and any displayed error. After an interruption, confirm the connection has recovered and new traffic is arriving before relying on it for net operations.
