Description of task

Use Net Monitor to send an APRS message from a running net to all checked-in participants or to one participant. Participants can also send messages to the net from their APRS radio or client using the M and MC commands.

Messages are recorded with the net and remain available in its archive after completion.

Prerequisites

  • For browser-based sending, sign in as the net owner or an administrator authorized to manage the net.
  • Have a running net with at least one checked-in participant. Expected or invited stations must check in before they can receive messages through the net's participant messaging controls.
  • Verify that the net selects an available communication instance that allows transmission.
  • Ensure the destination has been heard on an eligible connection so Net Central can route a directed message.
  • For radio-based sending, know the net callsign and check in by sending CI to it. Restricted nets require your callsign to be expected or invited.

Steps to accomplish

  1. Open Net Monitor and use the carousel to select the intended Running net. Confirm its callsign and name before composing a message. A Scheduled entry is a definition, not a running message destination.

  2. In the Messages section, select Send message.

  3. Set Recipient:

    • Leave Net, the default, to send a separate message to every currently checked-in participant.
    • Enter a checked-in participant's callsign to send only to that station.

  4. Enter the Message, up to 67 characters. Use concise wording. In this browser dialog, enter the message text directly; do not prefix it with the radio command M.

  5. Leave Request APRS acknowledgment checked if you want the receiving APRS client to acknowledge the message, or uncheck it if an acknowledgment is not needed.

  6. Review the recipient and text, then select Send message. This dialog submits immediately; it does not present a second confirmation. Review its status feedback and the delivery entries in Messages, then select Close to leave the dialog.

  7. For a single participant, you can instead select the station in Participants and choose Send Message in Participant details. The sender and recipient are fixed to the net and selected participant. Enter the message, select the acknowledgment option, submit, and confirm the displayed action.

Sending from a participant's radio or APRS client

Address an APRS message to the running net's callsign. After checking in, use one of these commands as the message text:

CommandExampleResult
M textM Supplies have arrivedRecords the message and forwards it to the other currently checked-in participants, with the sender's callsign identifying its origin.
MC textMC Please contact me by voiceRecords a message for Net Control in the console without forwarding it to all participants.

Include the command prefix when composing a radio message, and keep the complete message within your APRS client's supported length.

Verifying success

  1. Review Messages for the expected sender, recipient, text, time, and delivery status. Sending to Net creates individual outgoing entries for the checked-in recipients.
  2. Check delivery separately for each recipient. One station receiving the message does not prove that every participant received it.
  3. If an acknowledgment was requested, look for the delivery status to reflect the acknowledgment. ACK and REJ protocol messages are hidden from the displayed message text list; their effect is represented through delivery tracking.
  4. Ask the recipient to verify the message on their radio or APRS client when practical. A local send or protocol acknowledgment does not prove that a person has read the message.
  5. For a radio-originated M message, verify the console record and reception by another checked-in participant. For MC, verify it using the net owner's or administrator's console view.

Additional considerations

  • No route: Net Central uses a receiving connection or an eligible recently-heard route. Verify the participant has transmitted through an instance selected by the net, that the instance is Active, and that transmission is allowed. Merely adding an expected callsign does not establish a route.
  • Participation: Net-wide sends target currently checked-in stations. Checked-out and expected-only stations are not included. Radio M forwarding does not echo the message back to its sender.
  • Net Control: MC messages are not forwarded to the group and are hidden from non-managing users' message views. This controls application visibility; it does not make the original APRS transmission private.
  • Retries and restarts: Review delivery tracking before manually sending again. Pending outgoing messages are not retained for retransmission after an application restart.
  • History: The running monitor shows the latest 200 message entries. After the net is secured, the archive viewer can load additional history and generate the Message Report.
  • Archived nets: Archives are read-only. Select a running net to send new messages.
  • Kenwood source: Kenwood Serial uses its configured MYCALL as the RF source. Consider that identity when verifying how a transmitted message appears on another station.
